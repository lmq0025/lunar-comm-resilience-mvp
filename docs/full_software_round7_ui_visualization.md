## 2. 中文显示映射

统一入口为 `frontend/src/i18n/displayNames.ts`。显示优先级为：

1. 用户自定义中文名称。
2. 模型返回的中文显示名称。
3. 内置中文映射。
4. 可读的中文通用名称，并在详情保留内部 ID。

映射覆盖默认 12 个节点、4 项业务、节点和链路类型、后端故障库、传播事件、自愈策略与动作、运行阶段与状态、路径来源、14 项指标、工程结果字段和 16 项成果用途。内部 ID、YAML、API、数据库键和下载文件机器字段保持不变。

允许保留的英文包括内部 ID、HTTP/API/YAML/CSV/ZIP/SHA、QoS、TP/FP/FN、Mbps 等标准工程缩写，以及第三方 React Flow 的许可标识；这些内容不是面向用户的业务名称。

## 3. 统一拓扑组件

统一实现位于 `frontend/src/features/topology/unified/`：

- `topologyLayout.ts`：确定性三层布局，保留用户已保存的有效坐标。
- `TopologyStageAdapter.ts`：只做后端快照、路径和项目数据的显示适配，不复制仿真计算。
- `UnifiedLunarNetworkGraph.tsx`：统一 React Flow 画布、缩放、平移、适应视图和定位。
- `UnifiedLunarNode.tsx` / `DeviceGlyph.tsx`：统一节点和科研线框 SVG。
- `UnifiedLinkEdge.tsx`：统一曲线、线型、路径高亮和工程 Tooltip。
- `TopologyLayerBands.tsx` / `TopologyLegend.tsx`：层级背景和图例。

三层自上而下为月球轨道与空间通信层、月面通信网络层、地球地面通信层。月面层内部继续区分通信骨干与任务用户。默认确定性纵坐标分别为 60、255、465 和 675；同一项目和拓扑版本在业务、故障、运行和结果页面共享坐标。

编辑器优先采用保存坐标。用户可显式执行“应用分层布局”，该操作进入撤销/重做历史并可随项目保存，不会在进入其他页面时强制覆盖。只读仿真状态只改变视觉状态，不回写项目节点的 `active` 等属性。

## 4. 设备和链路视觉规则

SVG 设备图形包括月球轨道卫星、月球车、着陆器主枢纽、月面中继、地面天线站、科学载荷、高清相机、边缘计算设备和遥操作终端。

- 正常链路：灰蓝细实线。
- 当前业务路径：蓝色加粗曲线。
- 性能退化：橙色曲线。
- 故障失效：红色虚线和失效标识。
- 自愈后恢复路径：青绿色加粗曲线。
- 选中对象：额外描边并降低无关边透明度。

图例明确说明布局表示通信层级，不表示真实空间距离。第 6 步只显示非路由自愈动作，不显示第 7 步才产生的备用路径；第 7 步后恢复路径变为青绿色，失效主枢纽仍保持故障状态。

## 5. 页面接入与数据边界

业务配置、故障计划、仿真运行和结果分析复用同一套节点、边、布局与显示映射。拓扑编辑器继续保留拖拽、连线、添加、删除、属性编辑、视口保存和撤销/重做。

故障计划页面采用时间轴、故障列表、统一拓扑和详情面板布局。计划阶段只高亮故障目标，不将其提前标记为实际失效；第 4 步以后才使用后端故障快照。未知合法故障不会导致页面崩溃，无法定位时显示非阻断提示。

结果页顺序调整为结论摘要、核心可视化、业务和传播详情、完整表格及成果下载。原始表格与下载文件结构均保留。

## 6. 结果可视化数据来源

### 三阶段韧性恢复对比

`ThreeStageRecoveryPanel.tsx` 直接读取当前九步运行返回的正常、故障后自愈前和自愈后业务结果。阶段是离散快照，不表达连续时间采样。有效业务、可达数量、成功率、可用率、丢包率、中断时间、吞吐量和端到端时延均来自当前运行；非有限时延显示为“不可计算”，不会转换为 0。

### 五级自愈消融

历史实验源为 `outputs/experiments/healing_ablation/runs.csv`。核验得到 5/14、8/14、9/14、11/14、14/14，原始文件 SHA-256 为 `E3F40E4FBAAF8EB3C0FCE8AAFFD8AA177D3A0A3134815F0B6D08B21FBD091F63`。仓库内只读快照为：

- `data/baselines/healing_ablation_round7_runs.csv`
- `frontend/public/assets/healing_ablation_round7.json`

两份 CSV 已按字段和五行记录做语义一致性比较。界面明确标记为历史实验参考结果，不声称是当前单次九步运行推导出的四组额外实验。

### 故障传播因果链

`PropagationCauseChain.tsx` 使用现有传播路径、观测证据和预测对比结果。若后端仅提供整条路径累计概率与累计时延，数值只显示在链末端和详情中，不拆成虚构的边级数据。
